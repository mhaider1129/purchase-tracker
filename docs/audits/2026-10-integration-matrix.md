## Transaction and timing observations

Canonical P2P mutation, audit and outbox writes generally compose in the connected repository transaction. Inventory adapter composes in the same receipt transaction; it is not a separate ledger. Current GR and invoice services use locks/idempotency. Legacy contract finance often uses pool-level statements rather than one transaction. Legacy emails can occur inside still-open caller workflows. Generic response-finish audit is supplementary and best-effort.

`approvalTimingSql` is consumed by current dashboard reporting and identifies an active-time basis excluding approval holds. `procurementCycleTimeService` remains a raw elapsed helper, and other metrics use their own scoped SQL. A cross-workspace equivalence guarantee needs named KPI contracts and common fixtures; this audit does not declare all timing globally wrong or globally fixed.
