## Security boundaries and dependencies

`Release quality (master push)` → authenticated artifact/run/attempt/actual-checkout checks → `staging-rehearsal.yml` → fresh synthetic PostgreSQL + real containers + all sixteen transaction suites → retained immutable Actions evidence. There are no `deployments: write`, `contents: write`, environment secrets, SSH targets or production database URLs in this workflow. PR jobs cannot access the master-only rehearsal token path. The `workflow_run` consumer rejects forks, non-master/non-push runs, missing/expired/ambiguous artifacts and mismatched checkout commits before unpacking/execution.

Both applications derive from the same CI source commit. ZIP bytes are checked against authenticated GitHub SHA-256 metadata before bounded extraction; backend file manifests are independently checked against extracted bytes. The source digest now includes `scripts/staging/`. The source checkout is required clean for CI runtime rehearsal. Evidence is uploaded under immutable run/attempt artifact identities; local reports are explicitly non-promotable.

The synthetic builder can write only to the runner-created loopback `p2p_disposable_<random>` database. It refuses a populated public schema. Its administrative DB connection is closed and the temporary bridge is disconnected before the real application starts. Database and application runtime then share only an internal Docker network. No Docker socket is mounted into containers, no existing volumes are mounted, and inherited proxy variables are cleared inside containers. The build phase alone may fetch locked npm dependencies; it receives no application credentials.

## Completion limits

No production/Supabase compatibility, source data restore, live routing, persistent staging URL, external storage, SMTP/SAP, or owner UAT is certified by this rehearsal. Existing production release selection deliberately does not accept this workflow as a substitute for protected external staging acceptance or manual database evidence. Health-only success never establishes operational or financial acceptance.
