## Storage and ownership

The storage verifier performs no mkdir, format, mount or repair. `findmnt --mountpoint` must identify exactly `/var/lib/scop-staging`; the MAJ:MIN identity must be well formed and distinct from `/`. Expected UUID must be a valid 36-character filesystem UUID and equal the exact mount's UUID. The PostgreSQL directory and marker cannot be symlinks; its containing mount must still be that already verified dedicated mount, not root or a nested replacement. A missing/invalid result exits before Compose. Database bind remains `create_host_path:false` and initialized PG_VERSION remains required.

Tests execute a separately specified fixture only after rewriting both fixed paths into a temporary synthetic filesystem and mocking findmnt. Missing/wrong targets, root identity, malformed/absent values, wrong UUID, ignored failures, altered paths, CRLF shell bytes, absent initialization and weakened pre-start units fail. These tests do not inspect or mount a real volume.

Compose uses bind storage, not Docker named volumes. Volume ownership is the separately approved provider instance label/device/UUID mapping, mount verification and protected host configuration; no fictitious Docker-volume label is invented. Terraform server/firewall/volume names and labels include the same explicit instance. Host configuration and SCOP_INSTANCE must agree. Shared containers/networks require instance, purpose and role; release resources retain complete commit/request/image-derived provenance and protected retained-release cleanup. Source changes do not repair or adopt existing unlabelled resources. A dedicated host with unexpected resources is an incident, not a migration opportunity.

## Atomic firewall and dependency model

`host-policy.py` has pure validation/rendering functions plus a privileged, fixed-path host CLI. Development tests call only pure functions with mocked commands. The CLI accepts only `firewall` and `ownership existing|required`, requires root-controlled regular configuration files and the approved staging purpose/marker, and sanitizes failures. It accepts no URL, SQL, deployment, shell fragment or daemon override.

The firewall owns only `inet wici_scop`, tagged with staging purpose and instance. It holds a host flock, validates the complete input, inspects existing table ownership, runs nft --check, then submits one `nft -f` transaction containing any old-table deletion and the complete restrictive replacement. It never flushes the global ruleset or Docker's tables. Failure before commit makes no policy change; a kernel-rejected replacement retains the previous policy. A first-load failure blocks the required unit and therefore Docker/service/socket. No fallback opens connectivity. An interrupted/timeout result requires operator inspection of installed policy/configuration and unit state before further changes; never clear rules to recover access.

Input, output and forwarding defaults are DROP. IPv6 is denied before non-loopback connection allowances. Administrator SSH and hospital HTTPS are bounded to approved CIDRs. Host output permits only management replies, approved DNS TCP/UDP53, approved time peers UDP123 and the fixed GitHub CONNECT proxy. Proxy forwarding permits only explicit HTTPS CIDRs and bounded resolver traffic, with matching response rules. Docker's later filter/isolation chains remain authoritative for bridge-to-bridge traffic: the nft accept there does not bypass a later Docker DROP. Dedicated-host packet tests must prove these combined assumptions, NAT/conntrack behavior and unauthorized-destination denial. No real network-isolation PASS is claimed.

Cloud-init masks Docker service/socket once before installing packages. Both Docker units receive the reviewed `docker-staging.conf` dependency; the early firewall unit uses `DefaultDependencies=no`, after local filesystems/sysctl and before network-pre/Docker/socket, avoiding a basic.target → sockets.target → Docker socket → firewall → basic.target cycle. It remains installed across daemon restarts and has no rule-removing stop action. Units/templates are not enabled or installed by this PR. The initial provider firewall is attached before server creation and allows only explicit approved HTTPS/DNS/time destinations, never general outbound Internet. Actual cloud-init package transport may still be incompatible with that policy: fail closed and resolve NET-05 before provisioning/activation. Do not broaden egress to make apt or image pulls succeed.

## Inputs and controlled egress

`network-policy.example.json` uses documentation-only addresses and is not usable approval evidence. Real operators must separately approve and record matching Terraform variables and root-owned host `network-policy.json`, including source SHA and both configuration digests. Lists are bounded/unique, IPv4 is canonical, CIDRs are /24–/32, private/link-local/loopback/multicast/special targets are rejected. Host policy also rejects overlapping ranges. No DNS/time/web address defaults are supplied by Terraform. Approved SSH inputs are explicit numeric IDs from the separate staging project, not inferred from names or copied from production.

NET-05 remains BLOCKED. Transport rules alone do not establish trusted clock discipline, authenticated DNS/time, CDN address ownership, HTTPS package bootstrap, offline image provenance or safe patching. Host web access remains denied; preloaded digest-verified images and approved offline packages require a separately accepted delivery/custody process. GitHub CDN ranges can change: expire/review endpoint records and fail closed rather than adding broad ranges. No automatic firewall refresh, package updater, image pull or cloud API client is introduced.
